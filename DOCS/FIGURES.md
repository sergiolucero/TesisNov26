# Figures for the article

Generated by `SCRIPTS/make_figures.py` (300 dpi PNG, colour-vision-safe palette,
single/double column sizes). Everything is computed through the production code
paths — `run_optimization`'s config builders, `stoch.saa.Archive`,
`physics.fv2d` — or read from a finished run's artifacts; the only hard-coded
numbers are the measured costs in `fig7`, and the panel says so.

```
python3 SCRIPTS/make_figures.py                 # all seven (~3 min on CPU)
python3 SCRIPTS/make_figures.py --only plume    # one figure
```

## Where they are used

`SCRIPTS/make_figures.py` writes to `FIGURES/`; copies with article-facing names
live in `ARTICLE/figs/` (`pinn_vs_reference.png`, `conductivity_kl.png`,
`plume_policy_fields.png`, `compliance_and_peaks.png`, `search_trajectories.png`,
`chance_tail.png`, `reliability_certificate.png`, `compute_cost.png`). Three of
them are wired into the article as floats with captions and one in-text
reference each:

| article float | file | sits next to |
| :--- | :--- | :--- |
| `fig:certificate` | `reliability_certificate.png` | the 400-scenario Wilson table (§6.3) |
| `fig:chance` | `chance_tail.png` | the plume/reliability discussion (§6.3) |
| `fig:compute` | `compute_cost.png` | the cost table (§6.4) |

`ARTICLE/article.pdf` builds with `make` in `ARTICLE/` (latexmk) and `make check`
verifies there are no undefined references or citations.

## Regenerating the underlying data

```bash
# certificate ladders (the long pole: ~10 min each on one core)
python3 SCRIPTS/check_tail.py --metrics <run>/artifacts.zip \
    --config <run>/config_r0.yaml --m-scen 400 --ladder --json out/cert/f64_M400.json
```

`make_figures.py` never mutates a run; it only reads `metrics.json`,
`history.md` and the certificate JSONs. If a certificate file is missing the
corresponding panel is skipped with a note rather than faked.
